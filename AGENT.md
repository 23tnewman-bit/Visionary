# Visionary Local Agent

Visionary defaults to a local Ollama model and can optionally connect to OpenAI GPT through its API. Grok, Muse, Claude, and the Hugging Face/GitHub quick links open websites in the browser. Separate Hugging Face and GitHub API screens are available for account verification and repository actions.

## What this version can do

- Answer questions and discuss files that you explicitly load into its chat context.
- Read its own `VisionaryAgent.ps1` source, this guide, and text files saved in the `workspace` folder when you choose **Load Visionary files**.
- Read text or code files you select with **Add files...**. Loaded files are read-only reference and apply to the current app session.
- Use the folder-plus button beside the prompt to attach text or code files. Use the microphone button for speech input and **Speak replies** for text-to-speech. **Bluetooth** opens Windows Bluetooth settings; connect earbuds there and select them as the Windows audio devices.
- Choose **Ollama (local)** or **OpenAI GPT** in the model selector. **Refresh models** lists models installed in Ollama; **Get more models...** downloads one of the suggested small local models or a model tag you enter. Ollama downloads require internet and disk space, then chat runs locally. For GPT, enter an OpenAI API key and load its available model list. API keys are encrypted for the current Windows user; API use may be billed.
- Use **Connect APIs...** to save your own Hugging Face and GitHub tokens. Tokens are encrypted for your Windows account, persist between app openings, and are used only for direct requests to those services; they are not sent to the chat model. **Verify connection** is optional and tests whether a saved token still works. Public Hugging Face model search works without a token. In **Repositories...**, opening the GitHub tab automatically loads the latest 30 repositories when a token is saved; **Refresh list** reloads them. Refresh the Hugging Face account's model, dataset, and Space list manually; selecting one fills in its upload destination. A Hugging Face write token can create repositories and push app files. Spaces default to the static SDK; other SDKs may require a paid plan or compute billing. A GitHub token can create a repository after confirmation and push app files to a selected repository after confirmation. Fine-grained GitHub tokens need Metadata: read to list repos, Contents: write to push files, and Repository creation: write to create one. The quick-link buttons still open the websites in your default browser.
- **Repositories...** opens the repository screens. Refresh lists your GitHub repositories and your Hugging Face models, datasets, and Spaces. Selecting a Hugging Face repo fills in the destination and type. Create makes a new empty repository. The GitHub and Hugging Face push buttons upload exactly `VisionaryAgent.ps1` and `AGENT.md` from the app folder after confirmation. They do not upload model weights or user project files, and they do not delete remote files. A public destination makes those source files public. The chat model cannot invoke repository actions automatically. You must generate tokens on the provider's site and grant only the permissions needed: GitHub fine-grained tokens need Metadata: read to list repos, Contents: write to push files, and Repository creation: write to create one (or classic repo/public_repo scopes); Hugging Face needs a write token for repo creation and upload.
- **Performance...** shows current task time, available system RAM, Visionary RAM, Python/Ollama process RAM and CPU, loaded Ollama model/VRAM, and GPU memory when Windows or the image engine reports it. Chat, model downloads, and image jobs record elapsed time; task-time resource samples are saved every two seconds to `artifacts/performance/resource-samples.jsonl`.
- Image jobs check for at least 4 GB of free system RAM before starting the image engine. If Windows exposes GPU adapter memory counters, the app estimates AMD GPU free VRAM from the 16 GB capacity reported by the user and blocks image sizes below a small safety margin. If readings are unavailable, larger-than-512 images require at least 8 GB free system RAM before startup and are stopped if Windows still cannot verify GPU memory after the checkpoint loads. These checks reduce risk but cannot guarantee that a driver or model will not run out of memory.
- **Generate image...** starts AUTOMATIC1111 from `C:\stable-diffusion-webui\webui-user.bat` if needed, waits for its local API at `http://127.0.0.1:7860`, saves the result under `artifacts/images/`, logs the file path in chat, and opens the image. The API must be enabled with `--api`; a minimized console stays open while the image engine runs so its startup can be checked and it can be closed to free GPU memory. The local image engine must itself support your AMD GPU; monitoring does not add AMD backend support.
- To repair the existing `C:\stable-diffusion-webui` clone URL and enable its API, run `fix_stable_diffusion_repo.ps1` from the folder containing the Visionary installer once, then start `webui-user.bat` and wait until the WebUI has loaded a checkpoint.
- This version has no terminal or CLI runner. The browser buttons do not run commands or sign in to services.
- On explicit confirmation, index supported text and code files on ready fixed and removable drives. The index is saved in `workspace/pc_text_index.json`; relevant excerpts are sent to whichever provider is selected when you ask a question. Use **Delete index** to remove it.
- Automatically save each chat under `conversations/`; use **Open saved chat** and **New chat** to manage sessions.
- Save the latest assistant response as a Markdown or text artifact with **Save last answer**.
- Use **Propose file edit** to request a change to a selected small text/code file. Review the current and proposed versions side-by-side; approving creates a timestamped backup and writes the file. Edited code is never run by Visionary.
- Track project goals, status, what's working, fixes needed, next steps, and notes in **Projects**. Selecting **Use for this chat** adds that project context to the assistant and links the conversation.
- Keep app activity, startup errors, background-task errors, and unhandled UI/process errors in `logs/visionary.log`. It records exception and stack details without copying chat messages or API keys.
- For local Ollama chat, Visionary pauses requests when less than 2.5 GB of system RAM is available. If Ollama reports a model larger than the 16 GB GPU capacity the user reported, Visionary also checks a conservative system-RAM headroom estimate before loading it. These estimates reduce memory-related failures but do not predict every model/driver requirement exactly.

## Accuracy policy

- No general web search, trademark, domain, social, email, Shopify, or MCP connection is configured. Hugging Face model search is a separate provider API screen, and GitHub/Hugging Face account actions are limited to their dedicated screens. Do not claim those tools ran unless the user provides the result shown in the screen.
- Separate facts supported by loaded files from inference and unknowns. Say when current/external facts remain unverified. Never invent sources, URLs, citations, company results, or availability.
- If correcting an earlier answer, retract unsupported claims and do not replace them with more guesses.

## Limits

- Visionary is software and is not conscious or self-aware.
- In ordinary chat Visionary cannot directly edit or run files, control the computer, run terminal commands, log in to accounts, send email, or change Shopify. Repository actions require the separate API screens; the Hugging Face app-source push happens only when you click its clearly labeled button. File edits require the separate review and approval flow, and code is not run.
- With Ollama selected, prompts and context go to the Ollama service on this computer. With OpenAI GPT selected, chat history and relevant attached-file, project, and indexed-file context are sent to OpenAI. Hosted API use may incur charges. The app displays a confirmation before enabling it in a session. Image prompts go only to the local AUTOMATIC1111 API. Grok and the other quick links open in a browser only; they are not called by Visionary.
- Only selected text-like file types are loaded. Each file is limited to 50 KB and total loaded text is limited to 120,000 characters.
- Drive indexing skips hidden items, Windows/program folders, app-data and browser-profile folders, common credential folders, and code dependency folders. It indexes text/code types only (not images, PDFs, or Office files), up to 20,000 files and 80 million characters.
- Drive indexing stores readable text on-device and tries to redact common key/password fields and private-key blocks. Review the exclusions and delete the index when it is no longer needed.
- Proposed file edits are limited to 20 KB source files. Visionary returns a complete replacement, shows both versions, checks that the source did not change, and creates a timestamped backup only after approval.
